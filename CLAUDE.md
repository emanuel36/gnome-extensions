# gnome-extensions

Monorepo of GNOME Shell extensions, some imported from upstream with `git subtree --squash`
and maintained as my own code (not forks), the rest written here. Each extension lives in
`extensions/<name>/` with its own README, and has a row in the README's numbered table
(upstream links, `-` when there is none) and a short section with its mockup. The README's
"Upstream imports" table is the source of truth for imported code; update it whenever a
subtree is pulled again. Mockups are SVGs in `docs/images/` with made-up data, shown in
both the root and the extension README; update them when an extension's look changes.

READMEs describe what an extension does for the user: no tests, source paths, internal
APIs or design-doc links. Developer notes go here.

## Tests

Pure logic is covered by tests run with `gjs`:

```bash
for t in format stats usage sources; do gjs -m extensions/system-monitor/$t.test.js; done
gjs -m extensions/next-up/src/date.test.js
gjs -m extensions/todo/tasks.test.js
gjs -m extensions/todo/store.test.js
gjs -m extensions/panel-tidy/order.test.js
gjs -m extensions/window-layout/layout.test.js
```

`extensions/system-monitor/sources.test.js` is a smoke test against the running machine.

Start-of-project context (findings, local patches, decisions so far):
`docs/superpowers/2026-10-22-contexto-inicial.md`. Designs go in `docs/superpowers/specs/`.

## Target environment

- Ubuntu 24.04, GNOME Shell 46, X11 session. Everything must run on GNOME 46.
- The copies that actually run are in `~/.local/share/gnome-shell/extensions/`, installed
  from extensions.gnome.org (EGO). They are separate from this repo, and some were patched
  in place (see the context doc).
- GNOME 45+ caches extension modules: disable/enable does not reload changed JS. Restart the
  shell (X11: Alt+F2, `r`) or log out.
- Shell/extension logs: `journalctl --user -b | rg -i <name>`.

## Git

- Identity is set in this repo's local config (emanuel36, GitHub noreply email). Don't change it.
- `origin` uses the SSH host alias `github.com-emanuel36` (key `~/.ssh/id_emanuel36`).
  The GitHub repo does not exist yet. Never push unless asked.
- `git subtree add/pull -m` keeps only the last `-m`: pass a single message with embedded
  newlines.
- Bring in an upstream fix with
  `git subtree pull --prefix=extensions/<dir> <upstream-url> <branch> --squash`, then update
  the README's "Upstream imports" table.

### Commits

- Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`...), optional scope
  with the extension name.
- Subject of at most 50 characters; body lines of at most 72, mostly bullet points.
- Describe what changes and why at a high level; leave implementation details to the diff.

### Branch workflow

- Do every code change on a temporary branch named `<type>/<topic>` (e.g.
  `fix/next-up-countdown`, `feat/window-layout`), one branch per piece of work.
- Exception: rule updates and simple docs (CLAUDE.md, README, notes) are committed
  directly on `main`, with no branch or merge.
- When the work is done, clean up the branch history before merging: keep only the commits
  that are needed. A commit that fixes or adjusts an earlier one in the same branch is
  squashed into it (`git commit --fixup` + `git rebase -i --autosquash`, or equivalent).
- Then merge it into `main` with `git merge --no-ff` (never fast-forward), so each piece of
  work stays grouped under its merge commit, and delete the branch.
- Unpushed commits on `main` may be rewritten the same way; pushed ones never.
- Keep the `Squashed '<dir>/' content from commit ...` commits made by `git subtree` intact:
  `git subtree pull` finds them by their message.

## Licensing

- Keep each extension's upstream license file and copyright notices.
- GPL-3.0 files that get modified must carry a notice saying they were changed, with the date.
- Code combined from GPL-3.0 and MIT extensions must be released as GPL-3.0.

## Gotchas

- An extension whose `metadata.json` keeps the upstream UUID and the EGO
  `"_generated": "Generated by SweetTooth..."` key gets auto-updated by GNOME from EGO,
  overwriting local code.
