# Todo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GNOME Shell 46 indicator (`todo@emanuel36`) with a plain task list: add, tick
(done tasks go below), delete, drag pending tasks to reorder; then remove Todo.txt.

**Architecture:** Plain-JS ESM extension. List operations and the file format live in a pure
module (`tasks.js`) unit-checked with `gjs -m`. A small I/O module (`store.js`) loads and
saves the JSON file atomically. `indicator.js` is a `PanelMenu.Button` that rebuilds its
rows from the task array after every change; drag and drop is added last, on top of a
working list.

**Tech Stack:** GJS (ESM), GNOME Shell 46 (`St`, `Clutter`, `PanelMenu`, `PopupMenu`,
`ui/dnd.js`), `GLib`/`Gio`. No build step, no GSettings.

**Spec:** `docs/superpowers/specs/2026-10-22-todo-design.md` (approved mockup:
`.superpowers/brainstorm/296152-1792686398/content/todo-design.html`, local only).

## Global Constraints

- GNOME Shell 46, X11; `metadata.json` `"shell-version": ["46"]`, UUID `todo@emanuel36`,
  name `Todo`, no `_generated` key, no `settings-schema`.
- License MIT (copy `extensions/panel-tidy/LICENSE`, same holder and year). No code from
  Todo.txt.
- Style like `extensions/panel-tidy/`: 4-space indent, single quotes, `_private` methods,
  sparse comments, 100-char lines, sibling `./` imports only.
- Indicator registered with `Main.panel.addToStatusArea(uuid, indicator, 2, 'left')`
  (left box, after Activities and Next Up).
- Data file: `GLib.get_user_data_dir()/todo@emanuel36/tasks.json`.
- Copy (English): entry hint `New task…`, section header `Done · N`, empty state `No tasks`.
- Colours: titles `#e0e0e0`, secondary `#9a9a9a`, separator `rgba(255,255,255,.12)`,
  drop line `#3584e4`. Popup width 320 px.
- Icons (installed in Adwaita): bar `checkbox-checked-symbolic`, handle
  `list-drag-handle-symbolic`, delete `window-close-symbolic`; 16 px.
- Work on branch `feat/todo` (already created, spec committed). Add explicit paths, never
  `git add -A`.
- Testing in a real shell: `dbus-run-session -- gnome-shell --nested --x11` opens a nested
  shell in a window without touching the user's session (it reads the same
  `enabled-extensions`, so enable the extension first). Restarting the user's own shell
  (Alt+F2, `r`) is for the user to do.

## Review Focus

- Malformed or hand-edited `tasks.json` (bad JSON, a non-array, an item without `text`):
  never overwritten, moved to `tasks.json.bad`, list starts empty → `store.test.js`
  "malformed file is moved aside".
- First run (directory and file missing) and saving afterwards: directory is created →
  `store.test.js` "missing file loads empty" and "save creates directory".
- Pasted text with newlines/tabs or only spaces: collapsed to single spaces / ignored →
  `tasks.test.js` "addTask collapses whitespace" and "addTask ignores blank".
- Dropping a task on its own place, past the end of the list, or over the Done area: no
  change or clamped to the last pending slot → `tasks.test.js` "moveTask clamps" and
  "moveTask ignores done".
- An action on a task that no longer exists (double click on ✕ while the list rebuilds):
  no-op, no exception → `tasks.test.js` "unknown id is a no-op".

### Task 1: Task list logic

**Files:**
- Create: `extensions/todo/tasks.js`
- Test: `extensions/todo/tasks.test.js`

**Interfaces:**
- Produces (all pure, never mutate the input, return a new array or the same array when
  nothing changes):
  - `Task = {id: string, text: string, done: boolean}`; arrays are always in display
    order: every pending task, then every done task.
  - `addTask(tasks, text, id) -> Task[]` — new pending task at index 0. Text: whitespace
    runs (incl. newlines, tabs) collapsed to one space, trimmed; blank → input unchanged.
  - `toggleTask(tasks, id) -> Task[]` — pending → done, placed first among done; done →
    pending, placed last among pending.
  - `deleteTask(tasks, id) -> Task[]`
  - `moveTask(tasks, id, toIndex) -> Task[]` — `toIndex` is a position among pending tasks
    (after removing the moved one), clamped to `[0, pendingCount - 1]`; done or unknown id
    → unchanged.
  - `pendingCount(tasks) -> number`
  - `parseTasks(text) -> Task[]` — throws `Error` unless the JSON is an array of objects
    with string `id`, string `text`, boolean `done`; result normalized to display order
    (stable).
  - `serializeTasks(tasks) -> string` — `JSON.stringify(tasks, null, 2)` plus newline.

- [ ] **Step 1: Write the failing tests** in `tasks.test.js`, with the `check(name, actual,
  expected)` helper and exit code of `extensions/panel-tidy/order.test.js`. Fixture
  `t = [{id:'a',text:'A',done:false},{id:'b',text:'B',done:false},{id:'c',text:'C',done:true}]`
  and `ids = ts => ts.map(x => x.id)`:
  - "addTask puts new task on top": `ids(addTask(t, 'N', 'n'))` → `['n','a','b','c']`
  - "addTask collapses whitespace": `addTask([], '  buy\n milk\t ', 'n')[0].text` → `'buy milk'`
  - "addTask ignores blank": `addTask(t, ' \n ', 'n') === t` → `true`
  - "toggle pending goes first in done": `toggleTask(t, 'a')` ids → `['b','a','c']`, and
    `a.done` → `true`
  - "toggle done goes last in pending": `toggleTask(t, 'c')` ids → `['a','b','c']`, `c.done`
    → `false`; and on `[a, c(done), d(done)]` toggling `d` → `['a','d','c']`
  - "deleteTask removes any task": deleting `'a'` → `['b','c']`; deleting `'c'` → `['a','b']`
  - "moveTask reorders pending": `moveTask(t, 'b', 0)` → `['b','a','c']`
  - "moveTask clamps": `moveTask(t, 'a', 99)` → `['b','a','c']`; `moveTask(t, 'a', -3)` →
    `['a','b','c']`
  - "moveTask ignores done": `moveTask(t, 'c', 0) === t` → `true`
  - "unknown id is a no-op": toggle, delete and move with `'zz'` each return `t` itself
  - "pendingCount": `pendingCount(t)` → `2`; `pendingCount([])` → `0`
  - "parse round-trips": `parseTasks(serializeTasks(t))` → `t`
  - "parse normalizes order": parsing `[c(done), a]` → ids `['a','c']`
  - "parse rejects bad input": `'{'`, `'{}'`, `'[{"id":"a","done":false}]'` each throw
    (wrap in a `throws(fn)` helper returning a boolean)
  - "inputs are not mutated": after all of the above, `JSON.stringify(t)` equals its value
    captured at the start

### Task 2: Storage

**Files:**
- Create: `extensions/todo/store.js`
- Test: `extensions/todo/store.test.js`

**Interfaces:**
- Consumes: `parseTasks`, `serializeTasks` from Task 1.
- Produces:
  - `loadTasks(path: string) -> Task[]` — missing file → `[]`. Unreadable or
    `parseTasks` throws → `console.error` the reason, rename the file to `path + '.bad'`
    (replacing an older `.bad`), return `[]`.
  - `saveTasks(path: string, tasks: Task[]) -> void` — creates the parent directory
    (`GLib.mkdir_with_parents(dir, 0o700)`), writes with
    `Gio.File.replace_contents(bytes, null, false, Gio.FileCreateFlags.REPLACE_DESTINATION,
    null)` (temp file + rename, so a crash never truncates). Throws on failure; the caller
    logs it.
  - Synchronous I/O is fine: the file is tiny and written only on user actions.

- [ ] **Step 1: Write the failing tests** in `store.test.js`, each in a fresh directory
  from `GLib.dir_make_tmp('todo-test-XXXXXX')`:
  - "missing file loads empty": `loadTasks(dir + '/x/tasks.json')` → `[]`
  - "save creates directory": `saveTasks(dir + '/x/tasks.json', t)` then `loadTasks` of the
    same path → `t`
  - "malformed file is moved aside": write `'not json'` to `p`; `loadTasks(p)` → `[]`;
    `p` no longer exists; `p + '.bad'` contains `'not json'`
  - "save overwrites": save `t`, save `[]`, load → `[]`

### Task 3: Indicator and popup (no drag yet)

**Files:**
- Create: `extensions/todo/metadata.json`, `extension.js`, `indicator.js`,
  `stylesheet.css`, `LICENSE`, `README.md`

**Interfaces:**
- Consumes: everything from Tasks 1–2.
- Produces: `class TodoIndicator extends PanelMenu.Button` (registered with
  `GObject.registerClass`), constructed as `new TodoIndicator(path)`; it owns the task
  array, calls `saveTasks` after every change (catch and `console.error` on failure, keep
  the in-memory list), and calls `this._rebuild()` to redraw rows and the bar count.
  Task 4 adds drag to the pending rows built by `_rebuild()`.
- `extension.js`: `enable()` creates the indicator with
  `GLib.build_filenamev([GLib.get_user_data_dir(), this.uuid, 'tasks.json'])` and calls
  `Main.panel.addToStatusArea(this.uuid, indicator, 2, 'left')`; `disable()` destroys it
  and nulls the reference.

Behaviour to build (spec "Look" and "Behaviour"):

- Bar: `St.Icon` `checkbox-checked-symbolic` + `St.Label` with the pending count; the
  label is hidden when the count is 0. Use `panel-status-menu-box` like System Monitor.
- Popup content goes in one non-reactive item
  (`new PopupMenu.PopupBaseMenuItem({reactive: false, can_focus: false})`) so clicks on
  rows never activate a menu item and never close the menu. Inside it, a vertical box:
  `St.Entry` (hint `New task…`), then an `St.ScrollView` (vertical policy automatic,
  horizontal never) holding the rows. Cap the scroll view's height at 60% of the
  primary monitor's height, set when the menu opens.
- Entry: `clutter_text` `activate` → `addTask(tasks, entry.text, GLib.uuid_string_random())`,
  clear the entry, save, rebuild. On menu `open-state-changed` (open) give the entry key
  focus (`global.stage.set_key_focus(entry)`, in an idle if focus is lost to the menu).
- Pending row: handle icon, checkbox, wrapped label (`clutter_text.line_wrap = true`,
  `x_expand`), ✕ `St.Button`. Done row: an empty slot of the handle's width, checked
  checkbox, label with class making it `#9a9a9a` and struck through (`St.Label` text set
  through `clutter_text.set_markup('<s>…</s>')`, escaped with
  `GLib.markup_escape_text`), ✕.
- Checkbox: an `St.Button` with `toggle_mode` and a CSS box (14 px, 1.5 px border, 4 px
  radius; checked state filled `#e0e0e0` with an `object-select-symbolic` icon), click →
  `toggleTask`.
- `Done · N` header with a rule, only when N > 0; `No tasks` (dimmed, centred) when the
  list is empty.
- Row hover highlight `rgba(255,255,255,.08)`; ✕ at 35% opacity, 100% on row hover
  (track `hover` on the row with `track_hover: true` and a `:hover` pseudo class in CSS).
- `README.md` in the style of `extensions/panel-tidy/README.md`: what it does, where the
  file lives, the test commands, design link.

### Task 4: Drag to reorder

**Files:**
- Modify: `extensions/todo/indicator.js`, `extensions/todo/stylesheet.css`

**Interfaces:**
- Consumes: `moveTask(tasks, id, toIndex)` from Task 1; pending rows from Task 3.

Approach: `DND.makeDraggable(handle-or-row, {manualMode: false})` from
`resource:///org/gnome/shell/ui/dnd.js`, with the row's `_delegate` providing
`getDragActor()` (a clone of the row, styled `.todo-row-ghost`: `#454545` background,
shadow) and `getDragActorSource()`. The pending-list box is the drop target: its
`_delegate` implements `handleDragOver(source, actor, x, y)` (compute the insert index
from `y` against row allocations, show a 2 px `#3584e4` line there, fade the source row
to 25%, return `DND.DragMotionResult.MOVE_DROP`) and `acceptDrop(source, actor, x, y)`
(`moveTask`, save, rebuild, return `true`). Only the handle starts a drag, so clicks on
the checkbox and ✕ keep working. Remove the drop line and restore the source opacity on
`drag-end` and `drag-cancelled`.

The risk is the popup's own modal grab fighting the drag's grab (menu closing on drag
start, or no motion events). Check this first, in Step 1, before polishing.

**Fallback if `dnd.js` can't work inside the open menu:** a manual drag on the handle:
on `button-press-event` take `global.stage.grab(handle)`, follow `motion-event` to move
the drop line by the pointer's `y`, and on `button-release-event` call `moveTask` and
drop the grab. Same visuals, same `moveTask`. Record which way was used in the README.

- [ ] **Step 1: Spike the drag only** (no drop line yet), test in the nested shell:
  dragging a handle moves a ghost and the menu stays open. If not, switch to the fallback
  before going on.

- [ ] **Step 2: Add drop line, source fading, `acceptDrop`.**

- [ ] **Step 3: Check in the nested shell:** with tasks A, B, C pending and D done: drag C
